# 会抖的信号别折进"电平相等"的变更键(去抖交给边沿检测)

- 背景:一个事件通道靠"状态键变了就唤醒空闲会话"工作,原本只追踪 PR/MR 生命周期(open→merged/closed)。现在要让它在 MR 进入合并阻塞态(冲突 / 未解决评论)时也唤醒。
- 反例:把新的 `merge_readiness` 直接折进既有变更键(`seg_key`),靠"键不等 → 唤醒"复用现成机制
  - 看着"白送":往键里加一项就行。但这个便利叙事掩盖了前提——既有机制**隐含假设被追踪信号是单调、不回抖**的(生命周期确实如此)
  - `merge_readiness` 是**异步重算**的:刚 push 完会短暂读到 `checking`/unknown。于是 `conflict → checking → conflict` 把键翻成 `conflict → None → conflict`,**一次 push 触发两次唤醒**,中间一次还是空的"窗口变了"
  - 根因:把"什么值得唤醒"(策略 / 边沿)塞进了"现在是什么状态"(身份 / 电平)。身份键里掺策略,噪声就漏出来了
- 正例:键保持忠实、只表达生命周期(电平),把阻塞态单独做**边沿检测 + 迟滞**
  - 进入阻塞 → 唤醒;穿过 `checking`/unknown 窗口时 **hold 上一裁决**(异步态不算新信息);离开不唤醒;阻塞**类型**变了才再唤醒
  - 把这段抽成纯函数(`merge_block_event`),flicker 序列可单测——`conflict→checking→conflict` 必须只唤醒一次
- 关键判断:
  - **复用一个 diff/事件机制接新信号前,先校验新信号是否满足该机制的隐含输入不变量**(这里是"单调不回抖")。"加个字段就行"常常是把 T2(引入了新的时间语义)误判成 T0
  - **一个信号的已知危害(异步空洞)要传播到它的每个消费者**:同一信号被**电平消费者**(每轮重渲染的 banner)读是安全的,被**边沿消费者**(只在跃迁时动作的唤醒)读才会被咬。危害在感知层已识别(让 unknown 成一等公民),却没带到边沿消费者那层——这是最隐蔽的漏点
  - 噪声信号的正确形状是**迟滞边沿**(Schmitt 触发),不是电平相等
- 适用边界:
  - 适用于事件 / 唤醒 / 告警这类"跃迁触发动作"的场景,且信号会异步重算或可能短暂回抖(mergeability、CI 状态、健康检查,任何带 `checking`/`pending` 中间态的)
  - 不适用于单调状态机(生命周期 open→merged)——电平相等就够,加迟滞是过度设计;也不适用于纯轮询展示(电平消费者本就免疫抖动)
